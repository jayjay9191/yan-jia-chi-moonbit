# 设计手记：AI 工具定价核验（2026-11-15）

目标：比 Lexmount 二等奖 J006「AI岗位实习导航」更好、更完善。
打法：J006 的数据资产 + 证据链，加上 J085 的验证方法论，
再补齐 J006 的短板（公开仓库 + CI + 测试 + 能实际运行的工具 + 诚实 README）。

## 1. 从 J006 学了什么

J006（4 人队，360 条记录、274 在招、14 个采集日、103 个时间点）的赢法是
“把具体场景的数据做实”。学到的具体做法：

- **数据资产优先**：先有真实数据，再有工具。本项目种子数据就是用户
  Lexmount 那件作品的 20 条真实核验记录（2026-11-08，云端浏览器实际
  打开各官网逐页记录），不是现编的演示数据。
- **5 步证据链**：来源 URL → 原始记录 → 键 → 复核 → 实时页面。
  第一版先改成适合定价核验的 4 步（定价页 URL → 免费版/付费价/货币/
  计费 → 学生优惠/可达性 → 核验时间 + 状态）；2026-11-15 晚扩量时
  完整还原为 5 步——给每条记录加唯一记录键 `key`（APV-0001 起）与
  核验会话 `session`，`check <工具名>` 当场打印整条链。
- **明确标空白，不编造**：J006 明确写 263/274 条没有毕业年份、截止日期
  全部未披露。本项目 68/200“未核验到”付费价留空，CSV 里的“未显示”原文
  追加到备注里（“付费版原文：…”），信息不丢、价格不编。第三方转述的
  价（哪怕多家一致）一律不采纳，只认直接打开官方页看到的价。
- **生命周期意识**：J006 有状态机（在招/停招/重开）+ 每日 10:30 复采。
  本项目对应的是 verified_at + 30 天过期政策（`stale` 命令）+
  每条记录的 `history` 变动轨迹（只允许 6 种：无变化/涨价/降价/下架/
  新档位/未看到价）。2026-11-15 跑通第一次复核（11 条，1 条真实涨价），
  但轨迹量还很少（11 条 vs J006 的 197 + 130），要靠定期复核慢慢攒。
- **变现没学**：J006 有 ¥9.9 深度报告（自述，未见回执）。本项目没有
  变现设计，诚实缺口，待定。

## 2. 从 J085 学了什么

J085「周末加个餐」的赢法是验证方法论 + 可复用打包：

- **validate 0 错**：每条推荐带截图 + 页面 JSON + 原链接 + 核验时间，
  7 条规则测试全过。本项目对应 14 项检查（见 validate.mbt 顶部），
  真实数据 `verify` 0 错；265 项 MoonBit 测试 + 11 项 Python 测试。
- **数字带分母**：J085 的“84 家店、186 条团购筛出 26 套”每个数字都有
  分母。本项目汇总报告全部带分母（102/200、132/200、177/200……），
  README 实测表也一样。
- **可复用打包**：J085 是 Skill（SKILL.md + 脚本 + 配置示例），换个学校
  能复用。本项目对应的是 JSON 唯一事实源 + 生成器 + CLI：换一批工具、
  改 JSON、跑生成器，工具就能用在新数据上。
- **诚实边界**：J085 明确写“价格/库存会变，下单前去 App 里再核对”。
  本项目 README 同样写清“价格只在核验当天有效，30 天后需复核”。

## 3. 改了什么（相对 J006/J085）

- **PDF 自述 → JSON + 生成器 + 测试三重锁定**：J006 的数字只在 PDF 里，
  没法验。本项目数据在 `data/pricing.json`，生成器产出 MoonBit 数据模块，
  逐工具断言由生成器从 JSON 产出——数字改了，测试跟着变，不会悄悄过期。
- **无仓库 → 本地 git + CI 文件**：J006 没有公开仓库，演示链接 403。
  本项目本地 git init、多 commit，`.github/workflows/moon-test.yml`
  已写好（仓库建好后生效）。远程仓库、推送、报名表都没做——等用户指令，
  不擅自做。
- **死演示 → 可运行 CLI**：J006 的演示打不开。本项目 `list/verify/stale/
  report/check` 本地全能跑，演示命令在 README 里复制粘贴即跑。
- **5 步证据链完整还原**：第一版去掉了 J006 的“键”和“实时页面”两步——
  定价记录没有内部键；实时页面一步做不到（静态快照、不联网），不假装
  能做。2026-11-15 晚补齐：每条记录加唯一 `key` + 核验会话 `session` +
  `history` 变动轨迹，`check` 输出 5 步（来源 URL → 记录键 → 原始记录 →
  复核 → 实时页面）。“实时页面”这一步给的是可重走的链接，不是实时抓取——
  措辞上不夸大。
- **变动轨迹只记真实事件**：`history` 的 6 种变动类型里，“涨价/降价”
  必须新旧价俱全且不同（验证规则第 13 条当场卡住假轨迹）；没有第二次
  实测就没有变动记录。第一次复核就抓到 1 条真实涨价（智谱 GLM-5.1），
  证明这套机制不是摆设。

## 4. 什么是新增的（J006/J085 都没有）

- **三档核验状态**：已核验 / 部分核验 / 未核验到。J006 的记录全是
  “已核验”，没这个区分问题；定价核验里 Gemini（只在 Google One 页
  看到价）、Copilot（只核验到商业版）、海螺（只见到起步价）三条既不能
  写已核验（夸大），也不能写未核验到（丢掉已核验到的价），必须单列一档。
- **过期检测**：`stale` 命令 + 30 天政策 + 下次复核日。J006 靠每日复采，
  我们靠过期提醒 + 人工复核。
- **货币一致性规则**：货币字段与价格符号双向校验（USD 要有 $，JPY/CNY
  要有 ¥；未核验到的行货币必须为空）。J006 没有货币字段。
- **CSV 缺陷处理**：源 CSV 里 ChatGPT、Gemini 的千分位价格（1,400、1,450）
  没加引号，直接解析会切错字段。导入脚本按首尾字段定位 + 计费周期查表
  重组，并对 reachable、计费周期做交叉校验——这个坑是导入时当场发现的，
  不是事后补的（见 csv_to_json.py 注释）。
- **计费周期前缀归类**：`billing_category` 按开头归类，不按包含——
  “按量，无月/年订阅”里含有“月/年”，按包含会判错。这是写测试时
  抓出来的 bug（report 一度把按量算成 2 个、月/年算成 3 个）。

## 5. 诚实记录：还没追上 J006 的地方（2026-11-15 晚更新）

- **规模**：200 条 vs 360 条。还差 160 条；总目标 1000 条，继续扩。
- **核验天数**：2 天（2026-11-08、2026-11-15）vs 14 个采集日、103 个
  时间点。生命周期轨迹目前只有 11 条、1 条真实涨价，量还很小。
- **团队**：1 人 vs 4 人 + 5 个 Agent 角色（扩量用了 6 个核验子代理并行，
  但每条记录仍由人工抽查把关）。
- **变现**：不硬做。J006 的 ¥9.9 报告是自述、未见回执；我们的等价物是
  可交付的带证据链核验报告本身（本仓库 + `report`/`check` 输出），
  在 README 里诚实写清，不编“已跑通支付”。
- **公开程度**：本地仓库 vs 无仓库——目前只比 J006 好一点（本地 git +
  CI 文件），远程仓库还没建。
- **实时性**：静态快照 vs J006 的每日复采。`stale` 只能提醒，不能自动复核。

## 6. 扩量方法（2026-11-15 晚，20 → 200 条）

目标是今晚做到 200 个工具总数，先到 100 个已核验汇报一次。
做法、结果、教训都在这节；完整流程见 `docs/verification-process.md`。

**怎么挑工具**：六批、每批 30 个，按类别分（A 写作/文案/语法、B 图像/
设计、C 视频/音频/语音、D 编程/开发、E LLM API/云基础设施、F 办公生产力/
AI 搜索/其他）。先补原始 20 条里“未核验到”的同类工具（如 Notion AI、
Jasper、Runway、Suno、Groq、OpenRouter），再往外扩到公认的 AI 工具。
只挑有公开定价页的；没有公开定价页的工具不在这批里。

**怎么核验**：6 个核验子代理并行，每批一个，任务书一样：逐个打开官方
定价页读价，字段照现有格式填；官方页上找不到价的标“未核验到”、价格
留空，绝不从第三方汇总文章抄一个价来冒充官网价。每个子代理交 batch
文件前先做 7 条硬规则自查（状态三档、价格与状态双向一致、货币符号、
URL https、日期格式等），0 违规才交。

**合并与修正**：`scripts/merge_batches.py` 合并六批（每批一个 commit，
A～F 共 6 个），写盘前用 Python 镜像一遍 MoonBit 的 14 项检查，有问题
不写盘。合并时做了两处已确认的修正：① D 批 Tabnine 降级——官方定价页
已跳转至 Tricentis 联系页、实时页无价格，$39/$59 只来自 2026-09-05
官网存档快照，改为部分核验并写清来源；② D 批 v0 的备注改为引用官方
文档页 v0.app/docs/pricing（我亲自打开确认 Plus $30、Business $100）。

**第一次复核（20261115-R1）**：合并前先复核原始 20 条中带价的 11 条，
逐个重开官方页。6 条确认无变动（verified_at 更新到 2026-11-15），
1 条真实涨价（智谱 GLM-5.1：输入 ¥3.5→¥6/¥8、输出 ¥12.5→¥24/¥28；
GLM-5.1-Flash 在今日价目表已无此名，同价现为 GLM-5.3-Flash），
4 条未看到价（原价与 verified_at 都不动，只记“未看到价”轨迹）。
复核结论写死在 `merge_batches.py` 的 REVERIFY 表里，可审计。

**我的抽查**：合并后我亲自打开 8 条记录的官方页复核——Grammarly、
Jasper、Runway、Ideogram、Groq、Genspark 六条已核验的价格与官网逐字
对上；Notion AI、Leonardo.Ai 两条“未核验到”的空白属实（定价页 JS
渲染、文本抓取无价格；第三方转述价未采纳）。Suno 的官方页抓取被策略
拦截（子代理和我都打不开），记录保持“未核验到”，备注写清原因。

**里程碑**：已核验 100 个在 F 批合并时达成（90 → 102），commit 0791df5。
最终：200 条，已核验 102/200、部分核验 30/200、未核验到 68/200；
MoonBit 测试 262 项（200 条逐工具生成断言 + 23 黑盒 + 39 白盒），
补 3 条新测试后 265 项；Python 11 项；`verify` 0 问题；核心库 0 行未覆盖
（CLI 入口 28 行是工具链限制）。

**教训**：
- 黑盒/白盒测试里写死 20/8/3/9 的断言，扩量第一天就全崩——改成
  自洽断言（分档之和 = 总数、report 行由 report 结构体当场算），
  再扩到 1000 条也不用改测试。
- 生成器必须对缺字段报错：旧 JSON 没有 key/session 字段时，新生成器
  直接报“缺少字段”而不是静默跳过——严格比容错好，数据口径不能悄悄变。
- 逐工具生成断言跟着数据走是对的：200 条就是 200 条测试，测试数
  随数据涨，不用手写。
- 批次合并的 commit message 别照抄子代理的原始统计：D 批原始统计是
  “已核验 23”，Tabnine 降级后实际是 22——commit message 写了 23，
  数据是对的，message 错了。以后合并修正要先改 message 再提交。
