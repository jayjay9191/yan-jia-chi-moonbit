## 输入和输出共同选档

`estimate_token_window_cost` 同时按输入长度和输出长度选费率。每档的两个
长度区间都包含下限、排除上限。无上限时省略对应的 `max_*_tokens`。
如果两个区间在二维用量范围中重叠，或任何一组请求找不到费率，整笔估算会报错。
CLI 为 `estimate-token-windows <费率区间JSON> <请求用量JSON>`，整数用十进制字符串。
结果沿用 `cost_millionths_minor`，表示百万分之一最小货币单位。

[智谱官方 GLM-4.7 价目](https://docs.bigmodel.cn/cn/guide/start/pricing)提供三档
未缓存输入和输出单价。以下每种用量各模拟 1,000 次请求，可运行
`python scripts/verify_quote_scope.py` 独立复算。

| 单次输入 Token | 单次输出 Token | 输入 / 输出费率（元/百万 Token） | 费用（元） |
| ---: | ---: | ---: | ---: |
| 31,000 | 100 | 2 / 8 | 62.80 |
| 31,000 | 300 | 3 / 14 | 97.20 |
| 33,000 | 1,000 | 4 / 16 | 148.00 |
| | | 合计 | 308.00 |

测试将价目中的 K 按十进制配置。表中三组输入避开可能有歧义的边界，
另外对配置后的端点、重叠和费率缺口做断言。估算限未缓存用量。

### 缓存命中费用拆分

`estimate_cached_token_window_cost` 和 `estimate-token-cache` 复用同一组选档区间。
选档使用完整输入和输出量。命中的 Token 从普通输入量减去，再按同张价目表的
命中费率计价。输入每档提供 `window` 和 `cache_hit_minor`，后者表示每百万
缓存命中 Token 的最小货币单位报价。请求组提供 `usage` 和
`cached_input_tokens`，整数仍使用 JSON 十进制字符串。

沿用上表三组模拟请求，把每次命中量设为 20,000、0、33,000。官方缓存命中费率
分别是 0.4、0.6、0.8 元/百万 Token。独立复算结果为普通输入 **115.00 元**、
缓存命中 **34.40 元**、输出 **21.00 元**，合计 **170.40 元**。在同一组请求上
把命中量设为零，结果恢复为 **308.00 元**。缓存存储、写入和账单取整未纳入。
运行 `python scripts/verify_quote_scope.py` 可复跑并验证超额命中会报错。

## 按请求估算分档 Token 成本

`estimate_token_cost` 使用同次观测的输入和输出费率。每档提供输入长度的整数下限，
从 0 开始。MoonBit 按单次请求输入长度二分选档，再按两个单价计算整组请求的费用。
请求组可以用 `requests` 表示相同用量的重复请求。跨日期、套餐、币种或范围的费率
组合会被拒绝。计算使用标准库 BigInt，结果按百万分之一最小货币单位以十进制字符串
返回。例如人民币的 `50200000000` 等于 502.00 元。

命令行入口为 `estimate-token-cost <费率档位JSON> <请求用量JSON>`，
各整数金额和计数以 JSON 十进制字符串编码。仓库案例直接读取留存的官方价格观测：

```sh
python scripts/verify_quote_scope.py
```

[智谱官方价目](https://docs.bigmodel.cn/cn/guide/start/pricing)给出 GLM-5.1
短档输入和输出价 6、24 元/百万 Token，长档为 8、28 元。各 1,000 次请求，
输入分别为 31,000 和 33,000 Token，输出均为 1,000 Token，Python 独立复算
得到 210.00 元和 292.00 元。测试将 32K 显式设为 32,000 测试边界，
模拟用量避开 32,000 至 32,767 这一约定差异区。支持只依据输入长度选档的
未缓存请求，估算采用价目原值，未纳入折扣、税费和账单取整。

## 结构化报价对照

每次观测记录产品、套餐、币种、计价单位、付款周期、用量分档、适用范围、观测日期和来源。MoonBit 核对两条独立观测。结果为 `comparable`（可比）、`scope-mismatch`（口径不同）或 `evidence-gap`（证据不足），后两种返回原因而不产生差额。

```sh
python scripts/verify_quote_scope.py
```

命令从[可复跑观测](data/quote-observations.json)读取案例并调用 `compare-observations`。Midjourney 八个付款选项逐项验证，智谱 GLM-5.1 分开核对两个长度档和输入、输出计价，交叉比较不同用量档会返回口径差异。Tana 历史记录缺少与当前会议产品一致的身份凭证，当前官网 15 美元为年付折算月费，因此复跑返回证据缺口。

`compare-observations <旧观测JSON> <新观测JSON>` 接受两个 JSON 对象。金额 `amount_minor` 以最小货币单位记录，CLI 用十进制字符串保留 Int64 精度。年付填写一次续订的金额，按量填写每计价单位的金额。例如每人每月 15 美元、按年支付，填 `Annual`、`Seat` 和 `"18000"`。缺证据可留空或给 `null`。库接口为 `compare_quote_observations`。历史轨迹仍由 `quote-chain` 查询。

## 两次报价快照对比

```sh
moon run cmd/main -- compare-quotes 'Basic $10/月；Basic $96/年' 'Basic $11/月；Basic $8/月按年'
```

可导入 `jayjay9191/yan-jia-chi-moonbit` 并调用 `compare_quote_snapshots(before, after)`。可粘贴每行一条套餐的文本，支持 Windows 和 Unix 换行。空白行可跳过，行内两个分号之间的空报价仍会报待核对。该接口无需访问历史台账。结果含两侧报价问题和按套餐、付款周期匹配的差异。变化类型为 `amount-changed`、`basis-changed`、`added` 或 `missing`。本例只发现月付变化，年费用从 12000 分增至 13200 分。

同一口径的金额差异才提供前后年费用，JSON 中金额以字符串保留 Int64 精度。任一侧含矛盾或无法解析的原文时，先返回该侧问题，待补齐后再比较。

每条差异会列出存在的报价侧的货币代码和按席位标记，例如团队价 USD 和按席位 EUR。两侧币种与席位口径一致时，才有可比较的 `year_delta`，表示后次减前次的年费用差额，单位与年费用相同。由 $100/年变为 $96.01/年，差额为 `"-399"`。CLI 和公开接口均验证了金额、币种和席位字段。输出中的 `before_source`、`after_source` 保留原始报价片段，例如 `Standard $30/$24`；`before_quote` 则会显示展开后的付款选项 `$24/月按年`。

## 人数波动时的席位预算

```sh
moon run cmd/main -- seat-plan Pro '2,2,2,2,2,2,8,8,8,8,8,8' 'Pro $10/用户/月；Pro $96/用户/年'
```

`plan_seat_costs(raw, plan, demand)` 模拟 12 个月的席位需求。模型在年初预留固定数量的年付席位，每月超出的需求按月付补足，假定同套餐允许两种计费同时使用且单价固定。税费、折扣变化、最低起购量和供应商限制需另按合同核实。

总成本随年付席位数在各个月需求点之间呈线性，所以只需比较 0 和实际出现的需求数。等价费用优先选年付席位较少的方案。本例最优为预留 **2 个年付席位**，后六个月各补 6 个按月席位。全年混合模拟 **552 美元**，每月全按实付为 600 美元，按峰值全额年付为 768 美元。小规模场景用逐一枚举席位预留数验证。

### 人数预测不确定时

```sh
moon run cmd/main -- seat-risk Pro '2,2,2,2,2,2,2,2,2,2,2,2' '8,8,8,8,8,8,8,8,8,8,8,8' 'Pro $10/用户/月；Pro $96/用户/年'
```

`plan_seat_risk(raw, plan, scenarios)` 先算每个情景单独已知时的最低成本，再找一个所有情景共用的年付预留数，使最坏情景的额外成本最小。调用方可以提供 2–16 组需求，CLI 演示使用两组。模型继续假定同套餐可混用月付和年付、报价固定；不需要给情景分配概率。

在全年每月 2 席、全年每月 8 席两个情景中，最优折中为年付预留 **3 席**，各情景额外成本为 **96、120 美元**。最优点落在两个需求断点之间。算法利用最大额外成本的离散凸性二分求最小整数解，平手选较少预留数。三组小场景已与逐整数穷举对照。

在 CLI 命令末尾加 `25000`（美元报价即 250 美元），或在 API 传入 `annual_budget=25000L`，即可限制年初预付。每个年付席位 96 美元，预算只够 2 席。模型因此选择预留 **2 席**，预付 **192 美元**，相对各情景已知需求且不受预算限制时的最低成本，最坏额外成本为 **144 美元**。预算只约束年初预付，月付补足仍计入全年费用。输出 `annual_commitment` 为实际预付额，金额整数使用报价币种的百分之一。八个预算点用 Python 逐席穷举核验。

### 同时限制年初预付与每月补位

```sh
moon run cmd/main -- seat-risk Pro '2,2,2,2,2,2,2,2,2,2,2,2' '8,8,8,8,8,8,8,8,8,8,8,8' 'Pro $10/用户/月；Pro $96/用户/年' 38400 --monthly-cap 4
```

`monthly_cap` 限制任一情景、任一月份能加购的月付席位数。高峰需求减去该上限即为必须预留的最少年付席位，再与预付预算得出的最大席位数求交。例中必须预留 4 席，预付 **384 美元**，最坏额外成本 **192 美元**。预付上限少一美分就无可行方案，程序给出所需和可负担的年付席位数。各情景的 `peak_monthly_seats` 可直接核对，九组约束由 Python 枚举对照。额外成本仍相对于各情景已知需求时的无约束最低成本。

并列最优席位构成连续的整数区间。输出 `annual_seats` 为满足预算与补位限制的最小最优席位数，`max_optimal_annual_seats` 为最大值。求得最左最优点后，在右侧按同一最坏额外成本二分搜索。月付 10 美元、年付 60 美元，全年 2 席或 7 席时，**4 席与 5 席**并列，最坏额外成本均为 **180 美元**。预付预算 299.99 美元时只剩 4 席。四组约束由 Python 枚举全部可行整数。

如能接受一定的最坏额外成本，可传入 `regret_limit` 或在 `seat-risk` 末尾添加 `--regret-limit <百分之一货币单位>`。算法在凸成本曲线最优点两侧二分，返回同时满足预算、月补位和风险上限的完整区间 `allowance.feasible_seats`。在 2 席或 7 席预测的案例中，风险上限 240 美元允许 **3 至 6 席**。179.99 美元低于最优可达值 180 美元，结果省略可行区间并保留最优值。六组有解与无解的输入已用穷举核对。

传入 `scenario_weights` 或在 CLI 末尾加 `--scenario-weights 1,3`，可在可行席位区间内另求加权成本最低的方案。正整数权重与情景逐一对应，权重总和最多 256。输出 `weighted_plan.cost_numerator / weighted_plan.weight_total` 为精确加权平均成本，以报价币种的百分之一为单位。仍可读取原来的最小最坏额外成本方案作比较。2 席或 7 席案例中，在 240 美元风险上限及权重 1 比 3 下，方案预留 **6 席**，加权成本 **450 美元**，最坏额外成本 **240 美元**。预算裁剪、无可行解与权重并列结果都有穷举对照。

`weighted_plan.pareto_seats` 返回可行席位数中的帕累托区间。对区间内的任一席位方案，另一方案若能降低其中一项，就必然抬高另一项。算法用两条离散凸曲线的最低区间求交，或取两处最近的端点。加权成本并列时先选最坏额外成本更低的席位，再选更少的席位。权重为 1 比 3、风险上限 240 美元时，区间为 **5 至 6 席**，对应 **480 / 180 美元**和 **450 / 240 美元**的加权成本与最坏额外成本。八组独立测试枚举每个整数，并两两判断支配关系。

加权搜索使用私有 MoonBit 类型 `WeightedDemandCurve`。构建时合并相同需求断点，保存累积权重和加权需求量。每次求值找出严格高于预留数的断点，再以 `Int64` 算补位成本。预处理完成后，查询复杂度从扫描情景月份的 O(M) 降为 O(log K)，K 是不同的正需求数。内部对照覆盖空需求、重复断点、等于断点、最大权重及百万席位，全部与逐月直算完全一致。

## 优化最差一部分需求情景

在 `seat-risk` 中同时提供 `--scenario-weights 1,3 --tail-weight 2` 计算最差 2 个权重单位。每个情景的额外成本以事后最优成本为基准。排序后，边界情景只按所需权重计入。预付预算、月补位上限与最坏额外成本上限都会先限制可行区间。输出 `tail_plan.regret_numerator / tail_plan.weight` 是以百分之一货币单位计的尾部平均额外成本。

在两种需求恒为 2 席和 7 席、月付 10 美元、年付 60 美元、最坏额外成本上限 240 美元的案例中，5 个年付席位的最差半数平均额外成本是 150 美元。Python 将情景权重逐一展开并遍历全部可能席位，核对 8 组结果，包括预算与补位上限把候选压缩为一席或排除全部候选。

```powershell
moon run cmd/main -- seat-risk Pro "2,2,2,2,2,2,2,2,2,2,2,2" "7,7,7,7,7,7,7,7,7,7,7,7" 'Pro $10/用户/月；Pro $60/用户/年' --regret-limit 24000 --scenario-weights 1,3 --tail-weight 2
```

`optimal_seats` 给出所有并列最优席位的闭区间，本例为 [5, 6]。代表解 5 席的 `contributions` 分别计入情景 0 的 180 美元和情景 1 的 120 美元，各用一个权重。相同额外成本按输入顺序分配尾部权重，便于复算。


## 两套需求权重下的压力测试

两套权重必须有相同总量，才能比较同一段尾部。模型在每个席位上取两套尾部风险的较大值，再在预算和补位约束内求最小值及全部并列席位。

```powershell
moon run cmd/main -- seat-risk Pro "2,2,2,2,2,2,2,2,2,2,2,2" "7,7,7,7,7,7,7,7,7,7,7,7" 'Pro $10/用户/月；Pro $60/用户/年' --regret-limit 24000 --scenario-weights "1,3" --tail-weight 3 --stress-weights "3,1"
```

基准权重单独选 6 席。两套权重一起考虑后，`stress_tail_plan.optimal_seats` 为 [4,5]，代表解 4 席对应两套尾部均值 180 和 140 美元。按基准单独选 6 席时，压力情景下的尾部均值是 240 美元。独立脚本逐席展开两套权重并核对风险并列区间。

## 价格归一化（月均价折算，MoonBit 核心语义处理）

`normalize.mbt`：把不同写法的单档价格折算成可比的月均价（分取整），
核价结论由 MoonBit 算出来，不是 Python——Python 只负责把 JSON 原样搬进
`pricing_data.mbt`（生成器），14 项校验、状态判定、过期判定与归一化
都在 MoonBit 里。

- 能算的：`$8/月按年` → USD 8.00/月；`$96/年` → USD 8.00/月（年总价 / 12）；
  `¥990/年`（走工具记录的 currency 字段）→ CNY 82.50/月；`$8.33/月` → 833 分；
  按席计价（`$69/席/月`）单独标记“每席每月”；同档位按月价与按年折算月费率
  之差算年付节省率（Midjourney 四档均为 20%，见下）。
- 明确拒绝、不猜数：多档合写（`；`/`、`/`or` 分隔）先指定档位；按量（`/1M tokens`）、
  定制（`联系销售`）、免费档与付费价混写、无货币符号、无计费周期，一律拒绝
  并说明原因；`¥` 裸符号无法区分人民币与日元时也拒绝，须走工具记录的
  currency 字段；NT$/HK$/R$ 不认作美元，记 Other。不同货币之间不比较、不换算。

### 口径对齐（第二类语义处理，`align` 子命令）

同一档价格可写成年总价或按年计费的月费率。两侧都能归一化，且币种、月均整数分与按人头计费口径一致时，返回“价格口径一致”。套餐身份由来源页上的品牌、档位和计费周期确认。币种不明或文本含多个数字时，工具会说明拒绝原因。

对齐实例（`align` 子命令 2026-11-18 当场跑出；每处价格写法均出自 `data/pricing.json` 的真实记录原文或其档位写法）：

| 两处价格写法（来源） | 结论 |
| --- | --- |
| Midjourney Basic 年付月费率 `$8/月按年` vs Pika Starter 年总价 `$96/年` | 价格口径一致：均为 USD 8.00/月 |
| Midjourney Standard 年付月费率 `$24/月` vs Udio Pro 年总价 `$288/年` | 价格口径一致：均为 USD 24.00/月 |
| TripIt Pro `$49/年` vs KOA Rewards `$39/年` | 价格口径不同：月均价不同：USD 4.08/月 与 USD 3.25/月 |
| Emitwise `£7,500/年` vs TripIt Pro `$49/年` | 价格口径不同：货币不同：GBP 与 USD，不做汇率换算 |
| Grammarly `$12/用户/月` vs Playground 年付 `$144/年` | 价格口径不同：计费口径不同：一侧按席/按用户/按人计价，一侧不按人头计价 |
| Midjourney 全串（APV-0015）vs `$8/月按年` | 无法判定：第一处价格无法归一化：多档套餐：请先指定档位再归一化 |
| Power BI 全串（APV-0206）vs `$14/用户/月` | 无法判定：第一处价格无法归一化：多档套餐：请先指定档位再归一化 |

明确写出不支持的情形（诚实比贪多好）：

- 同一档位按月付与按年付的月费率不同时判不同：如 Midjourney Basic `$10/月按月` vs `$8/月按年`，月均价 1000 vs 800 分，判不同。口径对齐比的是价格本身，不是档位身份；要比同一档位的不同付费周期，用 `annual_saving_pct`（年付节省率）。
- 按年付与否不参与判定：只比货币、月均价、计费口径三项；按年付只影响月均价本身。
- 更细的计费单位（按次、按 token、按字符）都在按量拒绝里，根本进不了对齐；对齐只区分按席/按用户/按人 vs 不按人头。
- 任一侧是多档/按量/定制/免费混杂/无币种/无周期/裸 `¥`/空价格时，直接拒绝判定；两侧都被拒绝时报第一处的。
- 免费与免费判同（均为免费），免费与付费判不同。
- 货币不同不换算。C$、A$、NT$、HK$、R$ 等目前归到 Other，归一化仍能算本币数值，自动对齐和选低价均拒绝比较。

## 分工：人工 / Python / MoonBit

AI 辅助产生边界用例和整理报价差异。本版使用 Codex 辅助实现双条件费率匹配、缓存拆账和边界测试，按公开价目用 Python 整数独立复算。 取价以可打开的官网价目表为准。记录经生成器、MoonBit 验证规则和独立 Python 复算核对，人工检查币种、付款周期及产品是否属于同一口径。

| 步骤 | 人工 | Python | MoonBit |
| --- | --- | --- | --- |
| 采集 | 打开官网逐页读价、挑工具、记页面可达性。 | 一次性 CSV 导入与批次 JSON 合并，分配唯一记录键与核验会话。 | 不参与：CLI 不联网、不打开官网。 |

```sh
moon run cmd/main -- normalize '14-day trial, then $15/month'
```

前两次对齐均为 USD 8.00/月。第三次输出月均价不同（10.00 对 8.00），因为付款周期对应不同费率。MoonBit 测试核算年付相对月付省 20%。最后一条拒绝含试用数字的价格输入。人工负责锁定档位和提取报价，Python 将原始记录与复核会话生成 MoonBit 数据，折算、比较和拒绝判定在 MoonBit 的 CLI 内完成。


### 订阅预算

根据现有官方 Midjourney Basic 报价，月付首扣 USD 10.00，连续 12 个月 USD 120.00；年付首扣 USD 96.00，12 个月少支出 USD 24.00。相同比较也支持按席计费。输入报价必须使用相同币种和计费单位；整包报价的计费份数固定为 1。

### 真实调价 · Slack Business+

一条命令复跑官方公告的两套标准报价和 10 席年度预算：

```console
moon run cmd/main -- reprice slack 10
```

`reprice <席位数> <旧标准报价> <新标准报价>` 用于复核同一套餐调价。项目按币种、计费单位和实际付款周期校验，带促销标记、只明确起价、列有备选付款条件或周期不同的报价会返回退出码 2。调用者需要从来源确认两条确为同一套餐的标准报价。


Slack 于 2025 年 6 月 17 日发布 Business+ 调价公告。统一使用美元标准价、每位用户和相同付款周期比较。公告同步增加了功能，该案例衡量同名档位的账单变化。

| --- | --- | --- |
| 按年付 | USD 12.50 → 15.00 | USD 1,500 → 1,800，增加 300（20%） |
| 按月付 | USD 15.00 → 18.00 | USD 1,800 → 2,160，增加 360（20%） |

```sh
moon run cmd/main -- budget 10 '$12.50 per user per month billed annually' '$15 per user per month billed annually'
```

  JSON 一变测试跟着变。
- CSV 导入是一次性的：`python3 scripts/csv_to_json.py`（源 CSV 在
  `data/seed-pricing-2026-11-08.csv`，即那 20 条种子数据，已随仓库提交）。
  注意源 CSV 有个小毛病——ChatGPT、Gemini 两行的千分位价格（JP¥1,400、
  JP¥1,450）没加引号，直接用 csv 模块会切错字段；导入脚本按首尾字段
  定位 + 计费周期查表重组，并对 reachable、计费周期做交叉校验。
- 价格只在核验当天有效，官网随时会改；本工具的政策是
  30 天复核一次，`stale` 会标出过期记录。复核结果记进每条记录的
  `history`（变动类型只允许 6 种：无变化/涨价/降价/下架/新档位/
  未看到价），没有第二次实测就没有变动记录。
- 每条记录有唯一记录键 `key`（APV-0001 起按 JSON 顺序分配，追加不重排）
  与核验会话 `session`（如 20261108-LXM、20261115-A～F、复核 20261115-R1），
  `check` 输出 5 步证据链，任何人能按图索骥重走一遍。核验流程详见
  `docs/verification-process.md`。

# 0.1.4 轨迹与套餐审计

```sh
moon run cmd/main -- trajectory Tana
moon run cmd/main -- trajectory "智谱清言 / GLM"
moon run cmd/main -- trajectory-summary
moon run cmd/main -- classes Midjourney
moon run cmd/main -- recheck-queue 2026-11-20
python scripts/verify_review.py
```

轨迹按核实日期排序，同日保留记录顺序。六类由原始 `change` 字段决定。Tana 同口径单价变化为 -21%（显示值四舍五入），大幅涨价≥50%或降价≥30%的分级使用未舍入数值。多档、按量、币种、席位或付款周期不同的价格显示“幅度须逐档核对”，不会形成合成涨幅。连续两次未看到价会降低当前可观测状态，后续有效观察可恢复；下架保留历史并停止报价复核。日期校验覆盖实际月长与闰年。

套餐以命名身份作并查集合并，同付款周期逐对复用 `align_prices`，跨付款周期核对货币和席位并计算折扣。相同月均价不能证明套餐相同。月付和年付的 20% 差价是合法付款选项，所以跨周期不要求价格相等。紧凑 `$30/$24` 写法仅在该条原文明确给出月付/年付顺序时展开，不能解析的片段列入问题清单。

Midjourney 当前原文可解析成 8 种付款写法、4 个套餐，每档年付节省 20%，类内无矛盾。R3/R5 保存了可解析价格原文，身份集合一致；R1 的新旧价格字段均为空，输出“缺少复核当时的价格原文”，不把现价反填为历史。完整三次稳定性需要补回有来源的 R1 原文。

复核队列取前 20 条，分数为距核验天数 + 有调价/下架历史100分 + 未核验50分。同分按记录键排列。非法或未来核验日期记为待核对，给予3650分日期优先项。下架条目用于存档状态核对，停止常规定价复核。此处评分为工具内公开政策。
