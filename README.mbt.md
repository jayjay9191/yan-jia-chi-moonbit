# AI 工具定价核验 · MoonBit 版

1000 个常用 AI 工具官网定价的数据资产 + 5 步证据链 + 验证规则（MoonBit 实现）。

数据是真实核验结果，分四批：① 2026-11-08，用户 Lexmount 第二份作品的
20 条原始记录，Lexmount Cloud Browser 实际打开各官网逐页记录；② 2026-11-15
扩量 180 条（A～F 六批，每批 30 条），逐个打开官方定价页核验；③ 2026-11-15
晚再扩量 210 条（G～M 七批，每批 30 条），总数 410 条；④ 2026-11-15
深夜扩量 590 条（N～AG 二十批，AE 批 6 条暂扣未合），总数 1000 条。
未用第三方汇总文章，未编造未看到的价格。2026-11-15 还做了三次复核：
第一次复核（会话 20261115-R1）复核原始 20 条中带价的 11 条，发现 1 条
真实涨价（智谱 GLM-5.1）；第二次复核（会话 20261115-R2）复核 R1 未覆盖的
121 条，发现降价 2 条（Intercom Fin、Craft）、下架 1 条（Cline）；
第三次复核（会话 20261115-R3）复核 103 条（R2 的 34 条“未看到价”重开
+ 63 条部分核验与 15 条已核验抽样，9 条重叠且结论一致已去重），
发现降价 1 条（Tana Pro $19→$15/用户/月，两组独立核验一致）。

## Benchmark（1000 条数据，2026-11-16 实测）

测试方法：本机（4 核 CPU，MoonBit 0.1.20261104）上用 Python
`time.perf_counter()` 计 `moon run cmd/main <命令>` 的端到端耗时（含 MoonBit
启动与运行，不含首次编译），每个命令连续跑 6 次（分两轮、各 3 次），
取热缓存后的稳定值；首次运行因增量编译较慢（verify 首轮 1.80s），
表中是热缓存后的稳定耗时。

| 命令 | 耗时（热缓存，6 次实测） | 说明 |
| --- | --- | --- |
| `verify` | 约 0.09s（0.09 / 0.09 / 0.09 / 0.10 / 0.09 / 0.09） | 14 项检查，全量 1000 条 |
| `list` | 约 0.06s（6 次均为 0.06） | 列出全部 1000 个工具及价格状态 |
| `report` | 约 0.07s（0.07 / 0.07 / 0.09 / 0.07 / 0.07 / 0.07） | 汇总报告，含三份名单全量输出 |

结论：1000 条数据下三个常用命令都在 0.1s 量级，CLI 日常使用无等待感；
耗时主要来自 MoonBit 运行时启动，数据规模本身不是瓶颈。

## 演示命令（复制粘贴即跑）

```sh
export PATH="$HOME/.moon/bin:$PATH"
cd ai-pricing-verifier

# 汇总报告（带分母）
moon run cmd/main report

# 列出全部 1000 个工具及价格状态
moon run cmd/main list

# 跑全部 14 项验证规则，目标 0 错
moon run cmd/main verify

# 过期未复核的记录（超 30 天）
moon run cmd/main stale

# 单条证据链：5 步可追溯（来源 URL → 记录键 → 原始记录 → 复核 → 实时页面）
moon run cmd/main check Cursor
moon run cmd/main check "豆包"
moon run cmd/main check "ChatGPT / OpenAI"
moon run cmd/main check "智谱清言 / GLM"  # 有一条真实涨价轨迹

# 测试
moon test
python3 -m unittest discover -s tests_py
```

注意：工具名只接受全名，`check 黎明`这种简称查不到（和参赛管家一样）。

提交前检查：仓库配了 `.githooks/pre-commit`（提交前自动跑 `moon test`，
失败则阻止提交）。启用一次即可：`bash scripts/setup-hooks.sh`
（即 `git config core.hooksPath .githooks`）；不用时
`git config --unset core.hooksPath` 即可恢复。

## 数据说明

- 唯一事实源是 `data/pricing.json`，改数据只改 JSON，改完跑
  `python3 scripts/generate_data.py`（再跑 `moon fmt && moon test`）。
- 逐工具断言由 `python3 scripts/generate_tests.py` 从 JSON 生成，
  JSON 一变测试跟着变。
- CSV 导入是一次性的：`python3 scripts/csv_to_json.py`（源 CSV 在
  `~/workspace/goals/internradar/files/ai-pricing-verification/pricing.csv`）。
  注意源 CSV 有个小毛病——ChatGPT、Gemini 两行的千分位价格（JP¥1,400、
  JP¥1,450）没加引号，直接用 csv 模块会切错字段；导入脚本按首尾字段
  定位 + 计费周期查表重组，并对 reachable、计费周期做交叉校验。
- 价格只在核验当天有效，官网随时会改；本工具的政策是
  30 天复核一次，`stale` 会标出过期记录。复核结果记进每条记录的
  `history`（变动类型只允许 6 种：无变化/涨价/降价/下架/新档位/
  未看到价），没有第二次实测就没有变动记录。
- 每条记录有唯一记录键 `key`（APV-0001 起按 JSON 顺序分配，追加不重排）
  与核验会话 `session`（如 20261108-LXM、20261115-A～F、复核 20261115-R1），
  `check` 输出 5 步证据链，任何人能按图索骥重走一遍。核验流程详见
  `docs/verification-process.md`。
